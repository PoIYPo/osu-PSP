# osu!psp

Адаптация osu! для PlayStation Portable. Не порт: цель — не повторить десктопный osu!,
а сделать игру, в которую **реально играбельно на PSP** с его 480×272, аналоговым стиком
и четырьмя кнопками.

> Статус: ранняя разработка. Ядро (парсер карт, тайминг, геометрия слайдеров, правила
> osu!standard) готово и покрыто тестами. Рендерер, геймплей и звук — в работе.

---

## Что делаем и чего не делаем

**Делаем**

- чтение обычных `.osu` карт (v3…v14) прямо с Memory Stick;
- режим osu!standard с адаптированным управлением;
- 60 fps на реальном железе (PSP-1000/2000/3000, CFW ARK-4 / PRO);
- оффлайн-игру: одиночные карты, скор и точность локально.

**Не делаем (сознательно)**

- онлайн, мультиплеер, рейтинг, osu!direct;
- редактор карт;
- сторисборды и видео (только фон-картинка);
- остальные режимы (taiko/catch/mania) — до них дойдём только после играбельного standard,
  но парсер и модель уже учитывают их (`GameMode`).

## Как это играется

Главная проблема: в osu!standard надо целиться мышью, а на PSP есть только аналоговый стик
без тачскрина и с точностью «примерно туда». Поэтому управление адаптировано, а не скопировано.

| Действие | PSP |
| --- | --- |
| Двигать курсор | аналоговый стик (мёртвая зона 15%, сглаживание, чувствительность в настройках) |
| Удар по кругу | ✕ (или ○ — удобно чередовать на стримах) |
| Слайдер | зажать кнопку на голове — курсор **сам едет по пути** |
| Спиннер | вращение стика по кругу (или частое ✕/○) |
| Пауза / рестарт | L / R |
| Калибровка оффсета | SELECT |
| Выход | HOME |

Ключевая адаптация — **авто-следование слайдера**: провести стиком по безье-кривой
на экране 320×240 физически невозможно, поэтому после успешного попадания в голову
курсор привязывается к пути, а игрок только держит кнопку. Отпустил — слайдер потерян.
Это честно сохраняет ритм и сложность, убирая невыполнимую часть.

Дополнительно в настройках: «магнит» к нотам (курсор притягивается в радиусе ~1.2R)
и расширенные окна попадания (×1.5) — для игры на PSP-1000 с убитым стиком.

## Экран

Playfield в osu! — это фиксированные 512×384 (4:3). Экран PSP — 480×272 (16:9),
поэтому, как и в самом osu! на широких мониторах, поле центрируется, а по бокам
остаются панели HUD:

```
┌────────┬──────────────────────┬────────┐
│ score  │                      │ combo  │
│ acc    │   playfield 320×240  │  x123  │
│        │      (scale 0.625)   │        │
│        │                      │ 96.4%  │
└────────┴──────────────────────┴────────┘
```

Масштаб 240/384 = 0.625: круг CS5 имеет радиус 32 px в координатах карты → 20 px на экране
(диаметр 40 px). Этого достаточно, чтобы попадать стиком, но крайние ноты (x≈0…512)
остаются видимыми — в отличие от «растянуть на всю ширину», где поле пришлось бы обрезать.

## Архитектура

```
src/
  core/                 портируемое ядро, никаких API ОС
    types.h             Vec2, математика, размеры playfield
    beatmap.h/.cpp      модель карты + парсер .osu (v3…v14)
    timing.h/.cpp       BPM и slider velocity в любой момент времени
    slider_path.h/.cpp  геометрия слайдеров: Linear/Bezier/PerfectCircle/Catmull
    standard.h/.cpp     правила osu!standard: CS/AR/OD, окна, длительности, тики
  platform/
    psp/main.cpp        PSP: GU-инициализация, ввод, кадр (пока smoke-сцена)
  render/               (следующий этап) спрайты, шрифт, HUD
  game/                 (следующий этап) игровой цикл, судья, скор, HP
tools/
  osu_dump.cpp          CLI: разобрать карту и напечатать сводку
tests/                  юнит-тесты ядра (свой мини-фреймворк, без зависимостей)
```

Почему ядро отдельно и без зависимостей:

- его можно собрать и **протестировать на ПК за секунды**, не трогая PSP;
- оно же компилируется под MIPS без изменений (только `float`, без исключений в горячих путях);
- рендерер и звук подключаются как платформенные слои — их можно заменить/протестировать.

## Что уже работает

- Парсер `.osu`: секции, UTF-8 BOM, CRLF, комментарии, сортировка объектов и тайминг-поинтов,
  понятные ошибки с номером строки. Проверен на реальных картах форматов **v3, v7 и v14**.
- Тайминг: uninherited/inherited точки, SV, BPM, размер такта, поведение до первой точки.
- Геометрия слайдеров: адаптивное уплощение безье, точные дуги окружности, catmull,
  растяжение/обрезка до заявленной длины из файла, сэмплирование по расстоянию.
- Правила standard: радиус от CS, preempt от AR (с фолбэком AR→OD), окна 300/100/50 от OD,
  длительность слайдера по BPM×SV×SliderMultiplier, тики/репиты/хвост с позициями.
- 31 юнит-тест, включая сверку безье с аналитической длиной (162.32 px) и дуги (157.08 px).
- `osu_dump` — CLI для проверки любой карты без консоли.
- PSP-приложение: инициализация GU, отрисовка playfield 4:3, стик, выход по HOME.

## Дорожная карта

- **M0 — каркас и ядро** ✅ парсер, тайминг, слайдеры, правила, тесты, CI.
- **M1 — геймплей без экрана**: цикл игры, судья, комбо/скор/HP, симуляция сценариев ввода;
  headless-рендер кадров в PNG для визуальной проверки.
- **M2 — PSP-рендерер**: GU-спрайты, атлас скина, шрифт, HUD, курсор, ввод стика.
- **M3 — звук**: `sceMp3` со стримингом с Memory Stick, синхронизация по аудио-клоку,
  калибровка оффсета.
- **M4 — оболочка**: меню, список карт с MS, пауза, саундсеты.
- **M5 — полировка**: настройки ассиста, спиннеры, сохранение скоров, оптимизация под 60 fps.

## Сборка

### Локально на Windows (без прав администратора)

В репозитории нет зависимости от системного компилятора: скрипт скачивает портативные
GCC и CMake в `.tools/` (папка в `.gitignore`).

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_local.ps1
```

Скрипт скачает тулчейн (≈315 МБ, один раз), соберёт `osu_tests` и `osu_dump` и прогонит тесты.
Разобрать конкретную карту:

```powershell
.\build\osu_dump.exe "testdata\1800000.osu" --objects
.\build\osu_dump.exe --brief testdata\*.osu
```

### PSP (EBOOT.PBP) — через CI

Нативного pspdev под Windows нет, поэтому кросс-сборка живёт в GitHub Actions
(`.github/workflows/build.yml`, образ `pspdev/pspdev`): пуш → артефакт `osu-psp-eboot`
с `EBOOT.PBP` и `.elf`. Локально то же самое, если есть Linux/WSL:

```bash
cmake -B build-psp -DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-psp.cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build-psp -j
bash scripts/package_psp.sh build-psp/osu_psp.elf build-psp/EBOOT.PBP
```

### Установка на консоль

1. CFW (ARK-4 или PRO) на PSP.
2. Скопировать папку `PSP/GAME/OSUPSP/` с `EBOOT.PBP` на Memory Stick.
3. Запустить из XMB. Карты кладутся в `ms0:/PSP/GAME/OSUPSP/Songs/<папка>/`.

## Ограничения PSP, которые определяют решения

| Что | Значение | Следствие |
| --- | --- | --- |
| CPU | Allegrex MIPS32r2, до 333 МГц | бюджет кадра ~16.6 мс; никакого «тяжёлого» пост-процессинга |
| FPU | отсутствует, софт-float | только `float`, `double` — лишь при загрузке карты |
| RAM | 32 МБ (Fat) / 64 МБ (Slim) | держим в памяти одну карту + декодированные тайлы, без кэша песен |
| VRAM | 2 МБ eDRAM | CLUT8-текстуры, атлас скина, один-два фреймбуфера |
| Экран | 480×272 | playfield 320×240 + боковые панели HUD |
| Звук | `sceAudio` 44.1 кГц, `sceMp3` | MP3 стримим с MS, а не грузим в RAM |
| Носитель | Memory Stick | чтение карт и аудио — с диска, буферами |

## Грабли PSP-разработки (уже наступили)

Два бага, которые съели по циклу отладки, — записаны, чтобы не повторять:

1. **Без `psp-fixup-imports` приложение падает сразу после старта.** Симптом в PPSSPP:
   `Bad Execution Address`, прыжок на мусорный адрес вроде `0x0208d700`, PC внутри
   `.sceStub.text`. Это неразрешённые импорты `sce*`. Шаг обязателен для любого ELF,
   собранного вручную (в `CMakeLists.txt` он в `POST_BUILD`).
2. **Наложение дисплейного и depth-буфера даёт «телевизионный снег».** Один буфер
   8888 при ширине 512 — это `512*272*4 = 0x88000` байт. Каноничная раскладка VRAM:
   draw `0x0`, display `0x88000`, depth `0x110000`. Если depth положить на `0x88000`,
   картинка превращается в цветной шум без единого крэша в логе.

Полезно и то, что цвета GU — **ABGR** (`0xAABBGGRR`), а не RGBA: `0xFF0000FF` — это красный.
